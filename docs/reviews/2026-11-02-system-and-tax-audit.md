# SalesPilot: ตรวจระบบและภาษี ณ 2 พฤศจิกายน 2569

## ผลการตรวจ

ควรแก้ก่อนใช้หน้าภาษีเป็นตัวเลขยื่นจริง พบข้อผิดพลาดทั้งค่าลดหย่อนและความสอดคล้องของข้อมูลระหว่างการโหลด ส่วนการรวมลูกค้าควรแก้ก่อนใช้กับประวัติจำนวนมาก

ตรวจแบบอ่านโค้ดตามเส้นทาง View → Store → Service และรันกรณีจำลองจากฟังก์ชันจริง ไม่ได้อ่านหรือเขียนฐานข้อมูล production ไม่ได้แก้ application code และไม่ได้ deploy

แนวทางที่เล็กที่สุด: แยกสูตรภาษีเป็น pure function รับปีภาษี แบบ รายได้ และสิทธิที่ตรวจแล้ว ใช้ตารางกฎตามปี และเพิ่มการทดสอบตัวเลข ก่อนขยายฟีเจอร์ภาษีเพิ่มเติม

หลักฐาน: [สรุปลดหย่อนปี 2568 ของกรมสรรพากร](https://www.rd.go.th/fileadmin/user_upload/lorkhor/newsbanner/2025/12/PR1161_11122568.pdf) ระบุ Thai ESG ปี 2567–2569 ไม่เกิน 30% และ 300,000 บาท; [คู่มือ ภ.ง.ด.90 ปี 2568](https://www.rd.go.th/fileadmin/tax_pdf/pit/2568/Ins90_241268.pdf) ข้อกองทุน RMF และประกันบำนาญ

## ผลตรวจที่ตรงกับหลักเกณฑ์ในขอบเขตนี้

- หักค่าใช้จ่ายเหมา 60% สอดคล้องกับการขายสินค้าที่ผู้ขายไม่ได้เป็นผู้ผลิตตามประเภทที่กำหนด ไม่ควรเหมารวมว่า 40(8) ทุกกิจการใช้ 60%
- ตารางอัตราก้าวหน้า 0–35% และยกเว้นเงินได้สุทธิ 150,000 บาทแรกตรงกับตารางที่ตรวจ
- วิธี 0.5% ที่ไม่เกิน 5,000 บาทให้กลับไปใช้วิธีก้าวหน้า สอดคล้องกับคู่มือสำหรับกรณีเงินได้ที่ระบบรองรับ
- การหักเครดิต ภ.ง.ด.94 ตอนคำนวณ ภ.ง.ด.90 มีอยู่แล้ว แต่ยอดต้องเป็นภาษีที่ชำระจริง

## การตรวจสอบและข้อจำกัด

- npm run build ผ่าน (Vite 7.3.1) มีคำเตือน main chunk ประมาณ 1.83 MB / gzip 548 KB
- รันทดสอบสูตรจาก script setup ของ TaxView ด้วย Vue ref/computed และข้อมูลสมมติ ไม่เรียก Firebase
- ทดสอบ race ของ store และ failure ระหว่างรวมลูกค้าจากฟังก์ชันจริง โดยแทน service/Firestore ด้วยตัวจำลองที่ควบคุมลำดับและความล้มเหลว
- ไม่ได้ทดสอบครบทุกหน้าผ่าน browser หรือกับบัญชีจริง ไม่ได้รันชุด TestSprite ซึ่งมี flow เขียนข้อมูล
- ไม่พบ Firestore Security Rules ใน repository จึงยังสรุปความปลอดภัยของฐานข้อมูลจริงไม่ได้ Route guard เพียงอย่างเดียวไม่ใช่หลักฐานว่าฐานข้อมูลจำกัดสิทธิ์ถูกต้อง
